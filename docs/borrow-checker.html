Borrow Checker

BRW // 004

In this section

  • Philosophy

  • Safety Tiers
  • Error Reporting

Philosophy

GW implements a function-local, region-based borrow checker. It provides memory safety without garbage collection by enforcing ownership and aliasing rules at compile time.

The goal is to provide Rust-level safety with a simpler implementation that is faster to run and easier for the user to reason about.

The Algorithm

The checker operates on MIR using several coordinated passes:

  • Region Inference: Each reference introduces a region variable. Regions form a partial order based on outlives constraints.
  • Loan Tracking: Maintains a set of active loans (place, mutability, region) at every program point.
  • Aliasing Rules:
    • Mutable access: Asserts no other loan covers the place.
    • Shared access: Asserts no mutable loan covers the place.
  • Move Tracking: Dataflow analysis tracks initialization states; moves invalidate source locations.

Safety Tiers

GW acknowledges that sometimes the borrow checker is too restrictive. Three tiers of safety are provided:

Tier Enforcement
safe (Default) Full borrow checking and aliasing enforcement.
manual Aliasing checks suppressed; initialization tracking remains.
naked All safety checks disabled. Used for low-level kernels.

Error Reporting

Diagnostics for lifetime errors are designed to be actionable. Every error includes:

  • Primary Span: The location of the conflicting access.
  • Secondary Spans: Annotated locations of the original borrow.
  • Note Chain: Explanation of why the conflict occurred based on region inference.
  • Error Codes: Stable identifiers (e.g., E0042) for documentation lookup.
