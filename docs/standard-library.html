Module Structure

The standard library is partitioned into MGS-philosophers-themed modules, providing a comprehensive toolkit for systems and application development.

Module Domain
philosophers.memAllocators and memory primitives
philosophers.ioGeneric Reader/Writer gw pkgs
philosophers.fsFile system and path manipulation
philosophers.netTCP/UDP, HTTP/1.1, TLS
philosophers.foxTask spawning, channels, nurseries
philosophers.fmtPrint and format string engine
philosophers.replJSON/TOML/Binary serialization
philosophers.mathNumeric and vector math

Allocators

GW uses explicit allocator passing. The GW-CORE gw pkg defines the interface for all memory allocation strategies.

gw pkg GW-CORE {
    fn alloc(self: &mut Self, layout: Layout) -> !AllocError [*]u8;
    fn realloc(self: &mut Self, ptr: [*]u8, old: Layout, new: Layout) -> !AllocError [*]u8;
    fn free(self: &mut Self, ptr: [*]u8, layout: Layout);
}

Implementations

  • Heap: Wraps mimalloc or system malloc.
  • OuterHeaven: A fast bump arena for bulk allocations.
  • OuterHeavenVirtual: Reserves 1 TiB of virtual space, commits on demand.
  • Pool: O(1) allocation for fixed-size objects.

Concurrency

The fox task scheduler provides M:N work-stealing concurrency, modeled on a hybrid of Tokio and Go.

  • M:N Scheduler: One OS thread per CPU core with local deques.
  • Channels: Bounded MPMC channels (channel) with Vyukov-style ring buffers.
  • Structured Concurrency: Using nursery blocks for scoped task lifetimes.

I/O Subsystem

GW uses a completion-based proactor model, utilizing high-performance OS-specific backends:

  • Linux: io_uring (fallback to epoll)
  • macOS: kqueue with thread-pool file I/O
  • Windows: IOCP with ReadFileEx/WriteFileEx
