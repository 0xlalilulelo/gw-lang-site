Pipeline Overview

The GW compiler pipeline is designed for high-throughput and interactive use. It operates in a multi-stage process from source code to machine code.

.gw source  ──►  Lexer  ──►  Parser  ──►  AST
                                            │
                              ┌─────────────┘
                              ▼
                          Resolver  (name binding, frequency graph)
                              │
                              ▼
                          Type Checker  (bidirectional, cipher resolution)
                              │
                              ▼
                          Comptime Engine  (interleaves with type check)
                              │
                              ▼
                          MIR Builder  (CFG + SSA, lifetime annotations)
                              │
                              ├──► Borrow / Lifetime Checker
                              │
                              ▼
                          MIR Optimizer  (inline-small, const-prop, dead-code)
                              │
                              ▼
                          LIR Lowering  (target-shaped, register-flavored)
                              │
                       ┌──────┴──────┐
                       ▼             ▼
                  Fast Backend     LLVM Backend
                  (TPDE-style)     (release / cross)

Lexer & Parser

Lexer

UTF-8-native, written as a state machine on &[u8] with a small lookahead. Token stream is produced lazily; for incremental builds it is checkpointable per line. Reserved words are interned at startup into a phf perfect-hash map.

Parser

A hand-written recursive-descent parser with Pratt-style expression precedence. Hand-written is non-negotiable: error recovery, location precision, and IDE responsiveness all benefit. The parser is error-recovering, allowing the LSP to produce a partially valid AST after every keystroke.

Single-Pass Architecture

GW inherits HolyC's "no headers, no forward declarations" principle. The compiler is "single-pass" in the user-visible sense, but internally handles declarations before bodies.

  • Top-level items are collected before bodies are checked. The first traversal records signatures, class layouts, and constants.
  • Forward references are tracked through a fixup table. When name resolution encounters an unresolved identifier, it is revisited when the symbol is defined.
  • Mutually recursive functions are supported natively.

Type System

GW uses bidirectional type inference. This algorithm is preferred for its localized error messages and its ability to handle cipher trait bounds and overloading via UFCS.

Monomorphization: each generic function produces a fresh specialized function, cached in a global instantiation table. Cipher bounds are solved at instantiation time.

IR Design

GW uses three levels of intermediate representation to preserve information at the right level of abstraction.

IR Form Purpose Consumers
AST Tree, source-shaped Type checking, reflection Type checker, LSP, doc generator
MIR CFG of SSA blocks Borrow check, optimizations Borrow checker, MIR opt passes
LIR Register-flavored Codegen Fast backend, LLVM backend
